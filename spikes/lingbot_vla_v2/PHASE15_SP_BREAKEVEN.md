# Phase 15 — 跨 iGPU/dGPU 切分的通用不等式，和两个顺带量出来的单卡杠杆

## Context

用户的要求：**用 iGPU+dGPU 序列并行优化 denoise**，参考 PHASE14 §5 那张
「编译循环 206 ms 的时间去哪了」的四桶分解，在容器
`test-image_zy_scaler0260b2_lingbot_omni` 里验证。

Phase 14 已经把这件事**实现并实测过**了（context parallel 0.38×、sequence parallel 0.18×），
所以本阶段不是第十次否，而是做 Phase 14 没做的三件事：

1. **把否决从「逐个方案」升级成一个不等式。** §G..§N 是九次各自独立的拒绝，每次都得
   重新定价。本阶段给出一个只含四个实测量 `(T, k, w, C)` 的**必要条件**，一次封住
   「任何精确的模型内两设备切分」，并给出它翻盘的确切边界（§3）。
2. **补语料里唯一能翻盘的缺口：编译后的 iGPU。** §K2 起，每一个 iGPU 数字都是 eager 的。
   dGPU 编译后快 2.26×，如果 iGPU 也快 2.26×，SP 的地板会从 1704 ms 掉到 775 ms。
   **实测：iGPU 只快 1.20×**（§2）。这是本阶段最关键的新数，因为它是 `k` 的真值。
3. **在今天的容器里把 Phase 14 的三项重量一遍**，不引用历史值（§1）。

顺带量到两个和第二张卡无关的东西，价值超出本阶段：前缀长度曲线是**锯齿**的，
因此 PHASE9 的 P2 值 **−18.2 ms 而不是 −10.9**，而且它的收益**主要来自 bucket 选择、
不是来自删列**（§5）；以及 `num_steps` 是这个循环里最大的单个杠杆，**实测 −164.4 ms**（§6）。

全部测量：torch 2.12.0+xpu，checkpoint `/tmp/lingbot-vla-v2-perf`（基础模型），
eager fp16，`moe=dense`，`inference_mode`，B=1，`ZE_AFFINITY_MASK` 0=Arc Pro B60 /

## 0. 结论先放

**序列并行的分子是 21.5 ms，分母的算术地板是 937 ms。** 两个数都是实测，
而且都不含电线——把传输变成免费、重叠变成完美，账不变。

| 今天实测，同容器同基线 | denoise | vs 206.22 ms |
|---|---:|---:|
| 单卡，编译，出货配置 | **206.22 ms** | 1.00× |
| iGPU+dGPU **序列并行**，端到端 | **2456.33 ms** | **11.91× 慢** |
| ↑ 最好情况：电线免费 + 完美重叠 | 1657.01 ms | 8.03× 慢 |
| ↑ 再给 iGPU 只分 1 行（斜率外推） | ~1493 ms | 7.24× 慢 |
| ↑ 再当 iGPU 跑满 29 GB/s（纯算术地板） | 937.2 ms | 4.54× 慢 |
| 对照：一行 `num_steps: 10 → 2` | **41.79 ms** | **4.93× 快** |

**ring 内核仍然是对的**：action chunk 对单卡答案 rms **1.202e-3**，低于 fp16 地板 3.9e-3，
和 Phase 14 每一位相同。失败的不是内核，也不是电线（只占阻塞的 2%），是前提。

四个结论，其中第二、四两条的价值超出这次拒绝：

> **① 通用不等式（§3）。** 任何**精确**的模型内两设备切分要赢，**必要条件**是
> 「最便宜的跨越账单 < 最好的均衡切分收益」：
>
> ```
>              C · w      <      T / (1 + k)
>          360 × 0.109    <    206.22 / 10.36
>            39.24 ms     <       19.90 ms          ← 假
> ```
>
> **差 1.97×，而且这是给切分开到最大的口径**：完美可分、零替换、完美重叠、
> iGPU 调用免费、最便宜的载荷。把实测的 iGPU 单次调用地板 0.3375 ms 加回去，
> 收益掉到 8.18 ms，差 **4.80×**。
> 收益买得起 **183 次**跨越（含调用地板则 75 次），而循环的结构要求 **360 次**。
> **不等式是必要条件不是充分条件**，所以它为假是结论性的——这也是为什么必须在
> **编译**路径上算它（§3.3：eager 路径上它为真，而实测 SP 仍然是 0.18×）。
>
> **② `k` 是代码路径的属性，不是硬件的属性，而且编译让它变**大（§2）。同一份
> forward、同一天、两张卡：
>
> | 51 行 × 10 步 | eager | compiled | 编译加速 |
> |---|---:|---:|---:|
> | dGPU | 517.42 ms | **196.02** | **2.64×** |
> | iGPU | 2199.00 ms | **1834.72** | **1.20×** |
> | ⇒ `k` | **4.25×** | **9.36×** | |
>
> eager 的 4.25 和 §M §5 的「k(B=1) = 4.75」对得上。**编译后是 9.36**——因为 inductor
> 融掉的是 launch 开销，而 dGPU launch-bound、iGPU 不是（它卡在 29 GB/s）。
> §K2 的 12.9 来自一个独立的 MoE GEMM 微基准，不是整循环。
> **这条封住「写个更好的 iGPU 内核就行了」：inductor 已经试过，拿到 20%。**
>
> **③ 最优份额还是 0 行，编译路径上重新确认。** iGPU 编译后 50 行 1834.72 ms、
> 24 行 1657.01 ms，斜率 6.835 ms/行，**0 行截距 ~1493 ms**——是整个单卡循环的 7.2 倍。
> 序列并行**复制权重**，所以 iGPU 拿几行都要把 27.2 GB 流一遍。
>
> **④ 前缀长度曲线是锯齿的，而这值 16 ms（§5）。** 223 个 key（`Lk=274`）比
> **214** 个 key（`Lk=265`）**快 16.0 ms**，三次重复散布 ±0.16 ms——**活儿更多反而更快**。
> 所以 206.22 ms 里至少 16 ms（7.8%）是**内核配置**，不是工作量。
> 直接后果：PHASE9 的 **P2 实测 −18.2 ms 而不是估的 −10.9**，
> 而且它的收益**主要来自落在快分支上，不是来自删那 63 列**（§5.2）。

## 2. Gate 2 — 新数：编译后的 iGPU

语料里 `k` 的每一个来源都是 eager 或一个独立微基准。这是唯一能翻盘的地方：
dGPU 编译后快 2.26–2.64×，如果 iGPU 同比例，SP 的地板会从 1704 掉到 775 ms。

`ZE_AFFINITY_MASK=1`，同一份 `sp_predict_velocity`，同一天，iters 3 / warmup 2：

| 给 iGPU 的 action 行 | eager | | compiled | | 编译加速 |
|---:|---:|---:|---:|---:|---:|
| 50 / 50 | 2199.00 ms | 1.000× | **1834.72 ms** | 1.000× | **1.20×** |
| 24 / 50 | 1921.60 ms | 0.874× | **1657.01 ms** | 0.903× | 1.16× |

> **iGPU 吃不到 inductor 的红利：1.20× 对 dGPU 的 2.64×。** 理由是结构性的——
> inductor 融掉的是 launch 开销，§F1 量过 dGPU 循环 dispatch-bound（286.5 ms 请求里
> 282.6 ms 是 host 提交），而 iGPU 卡在 29 GB/s 的带宽上，没有 launch 可融。
>
> 于是 **`k` 从 eager 的 4.25 变成编译的 9.36**，而**出货配置是编译的**。
> 这条比「iGPU 慢」本身更有用：它说明 `k` 不是一个硬件常数，而是
> 「dGPU 在这条路径上被优化了多少」的函数。**dGPU 每一次变快，`k` 就变大，
> 第二张卡的经济账就更差。** 任何将来的单卡优化（§6 的 −164 ms 尤其）都会
> 让 iGPU 更没机会，不是更有机会。

线性外推（两点，斜率 6.835 ms/行）：

| iGPU 编译，0 行截距 | **~1493 ms** | 实测 |
|---|---:|---|
| 27.2 GB ÷ 29 GB/s，纯 DRAM 算术地板 | 937.2 ms | 算术 |
| ⇒ 达到其带宽的 | 62.8% | |

> **序列并行里 iGPU 参与的最小代价是 ~1493 ms，是整个单卡循环的 7.24 倍。**
> 与份额无关（复制权重），与内核质量无关（算术地板已经 4.54 倍）。**最优份额是 0 行。**

## 3. Gate 3 — 通用不等式

§G..§N 是九次独立定价。本节把它们的公共结构提出来，代价是一个假设（精确切分），
收益是一次封住整族，并给出翻盘边界。

### 3.1 四个量，全部实测

| 符号 | 含义 | 值 | 来源 |
|---|---|---:|---|
| `T` | 编译循环，出货配置 | **206.22 ms** | §1.1 |
| `k` | iGPU / dGPU，**编译**路径，同一份 forward | **9.36** | §2 |
| `w` | 一次跨设备往返，本机最便宜载荷，不含计算 | **0.109 ms** | §1.3 |
| `C` | 每请求跨越次数 | **360** | 结构，见 §3.2 |
| `c₀` | iGPU 单次调用地板（可选项） | 0.3375 ms | §2 |

### 3.2 为什么 `C = 360` 是结构决定的，不是实现选择

这个循环只容许两种切法：

1. **切一个并行维度**——prefix key（337）、suffix 行（51）、attention head（32）、
   专家（32）。每一个都必须在**同一个 layer-step 内的一个非线性处**汇合：
   attention 是对 key 的归约，所以两侧的 partial `(out, lse)` 必须在 `o_proj`
   之前合并；`forward_dense` 的最后一步 `etd,te->td` 是对专家轴求和，所以专家切分
   必须在残差加之前合并。而 `o_proj` 之后是残差、`post_attention_layernorm`、MoE，
   全是非线性，两个分支**带不下去**。⇒ 36 层 × 10 步 = **360** 次。
2. **切一个串行阶段**——层、Euler 步。B=1 下**并发度为零**：层 `m` 的输入是层 `m−1`
   的输出，步 `s+1` 的 `x_t` 是步 `s` 的 `v_t`。PHASE13 §5c 给最接近的变体定过价
   （减层 int4 整模型放 iGPU，217.8 ms/tick 对同样压缩留在 dGPU 的 109.2，**2.0× 亏**）。

**没有第三种。** 这也正是唯一通过的那个拓扑（PHASE10 speculative）为什么通过：
它切的是**草稿/验证这个职责**，一个 tick 一次往返，不是 360 次。

> 补一句 §3.2 的坏消息：**切两个桶不摊销跨越，是乘。** attention 的汇合点
> （`o_proj` 之前）和 MoE 的汇合点（残差之前）是同一层里的两个不同位置，
> 两个都切就是 720 次。唯一的例外是纯行切分——它一次交换同时覆盖 attention 和 MoE
> ——但它在 MoE 桶上一分不赚（72.00 MiB/layer-step 的专家权重与行数无关）。

### 3.3 不等式

一个把工作量的 `f` 份放到慢 `k` 倍的设备上的完美切分：

```
wall(f) = max( (1-f)·T , k·f·T ) + C·w
最优     f* = 1/(1+k)
收益     T/(1+k)          ← 完美可分、零替换、完美重叠下的全部收益
```

**必要条件：** `C·w < T/(1+k)`

| | 编译（出货） | eager |
|---|---:|---:|
| `T` | 206.22 ms | 466.46 ms |
| `k` | 9.36 | 4.25 |
| 收益 `T/(1+k)` | **19.90 ms** | 88.85 ms |
| 账单 `C·w` = 360 × 0.109 | **39.24 ms** | 39.24 ms |
| 不等式 | **假，差 1.97×** | 真，余 49.6 ms |
| 买得起的跨越数 `N*` | **183** | 815 |
| 结构要求 | **360** | 360 |

加上实测的 `c₀`（`iGPU(f) = C·c₀ + k·f·T`）：

```
平衡点   f = (T − C·c₀) / (T(1+k)) = 84.72 / 2136.44 = 3.97%
wall     198.04 ms        收益 8.18 ms        N* = 75      差 4.80×
校验     iGPU = 121.5 + 9.36×0.0397×206.22 = 198.1 ≈ dGPU 198.0   ✓
```

### 3.4 这个不等式是必要条件，不是充分条件——而这正是它有用的方式

**eager 那一列为真，而实测的 eager SP 是 0.18×。** 所以不等式为真什么都不说明。

理由是 `f* = 1/(1+k)` 假设**完美可分、零替换**，而序列并行**复制权重**：
iGPU 的成本**根本不随 `f` 缩**（§2：0 行 1493 ms）。充分条件被违反了。

> **所以只有「为假」是结论性的，而它在编译路径上为假。**
> 这是本阶段坚持要量编译 `k` 的全部理由（§2），也是 §8 ⑤ 那个坑的另一种说法：
> **在 eager 路径上算这个不等式会得到一个「可以试试」的错误许可。**

### 3.5 翻盘边界（这是为了不把结论说过头）

| 要让不等式成立，必须 | `c₀` 免费 | 含实测 `c₀` |
|---|---:|---:|
| 单次跨越降到 | 0.0553 ms（快 **2.0×**） | 0.0227 ms（快 **4.8×**） |
| 第二张卡的 `k` 降到 | **4.26** | **1.16** |
| 跨越次数降到 | 183 | 75 |

> **`k* = 4.26` 意味着第二张卡必须不慢于 B60 的 4.26 倍——含调用地板则 1.16 倍，
> 即基本上得是第二张 B60。** 所以这个定理是**设备对**的属性，不是循环的属性，
> 必须这样陈述。它**不**说「这个循环不能切」；它说
> **「在这个设备对上，没有任何精确的模型内切分能赢」**。
>
> 而 `k` 会随 dGPU 侧的优化**变大**（§2），所以这个边界只会越来越远。

### 3.6 分桶（把 §5 那张四桶表接进来）

收益 `= B/(1+k) = B/10.36`：

| 桶 | 大小 | 切开的收益 | 结构要求跨越 | 买得起 |
|---|---:|---:|---:|---:|
| 286 个 prefix token 的 attention | 33–35 ms | 3.19–3.38 ms | 360 | 29–31（按 0.109）/ 7（按它自己的 0.446） |
| 随 51 行缩放的全部 | ≤ 24.6 ms | ≤ 2.37 ms | 360 | 22 |
| MoE GEMM | ~90 ms | 8.69 ms | 360 | 80（按 0.109）/ 56（按它自己的 0.155） |
| 其余 | ~60 ms | 5.79 ms | 360 | 53 |

> **没有一个桶买得起它自己结构要求的 360 次跨越，最窄的差距是 4.5×（MoE）。**
> 四桶来自不同代码路径，不要精确相加（Phase 14 §5 的告示照样成立）；
> 该引用的是 §3.3 的整循环数，它只用 `T`。

### 3.7 这个定理最弱的一个假设：**精确**

`C ≥ 360` 是「每个 layer-step 都要 bit 级汇合」的推论。**放掉精确性，这里没有任何东西
再约束跨越次数**——而这恰恰是 PHASE10 走的那道门（一个 tick 一次往返）。

仓库里既有这道门又有先例：`phase10_kv_staleness_probe.py`、`spec_tau = 0.15` 的宽闸门。
所以定理的正确陈述是：

> **在这个设备对上，没有任何「精确的、切模型内部并行维度」的方案能赢。**
> 不是「什么都不能切」。异步/过时/投机类的方案**不被本定理约束**，
> 要单独定价——而它们唯一已知的成功实例（PHASE10）切的不是模型，是职责。

**本阶段没有穷举异步类方案。** 一个并行的设计空间穷举（6 个 lens + 对抗定价）
跑到一半会话结束，没有结论可引用。所以「没有未被证伪的变体」这句话
**本文件不说**——本文件只说结构论证（§3.2）加上 §G..§N 的九次拒绝。

| **dGPU + iGPU 序列并行** | **2456.33 ms** |
| 每 layer-step ring 交换（104 KiB/hop，2 hop，360 次） | 4.939 ms |
| 阻塞在交换里 | 1947.67 ms（5.410 ms/layer-step，**占墙钟 79%**） |
| action chunk vs 单卡 | **max_abs 2.637e-2，rms 1.202e-3** |
| 最好情况：电线免费 + 完美重叠 | max(509, ≥1948) = **1947.67 ms** |

> 探针打印的 0.18× 是对它自己的 **eager** 单卡基线 453.98；
> **对出货的编译基线 206.22，它是 11.91× 慢（0.084×）。** 引用时说清是哪个分母。

三项和 §1/§2/§3 的独立测量对账：

```
阻塞 1947.67 ms/循环  =  5.410 ms/layer-step
  iGPU 那半（§2，编译 24 行 1657.01 ms）      4.603 ms/layer-step   85%
  纯电线（§1.3，--split wire）                0.109 ms/layer-step    2%
                                            ----
  和                                        4.712（对实测 5.410 少 13%，
                                                  差在重写税和 eager worker）
```

> **阻塞的 85% 是 iGPU 在算，2% 是电线。** 和 Phase 14 的 98%/2% 同一个方向。
> **把电线变成免费，账不变**：`max(509, 1948) = 1948`。

**精度是好消息，而且不变。** rms **1.202e-3** 低于 fp16 地板 3.9e-3，
和 Phase 14 每一位相同——两个 rank 都用 fp32 累加自己那些行的 softmax。
**ring 在这里不花精度；这个模型真要做生产级 SP，数值上站得住。** 输的是经济账。

## 5. 副产品 A — 前缀长度曲线是锯齿的，值 16 ms

§1.1 的曲线只取了 286/143/72/8 四点，看着单调。Phase 14 §9 注意到
「214 → 143 那一段占了整个降幅的大部分，非线性，大概是分块/对齐效应，**没有追下去**」。
本节追了，因为 PHASE9 的 P2 目标长度（223）正好落在那一段里。

### 5.1 曲线

编译，dGPU，10 步。三次独立运行，A 用 iters 6，B/C 用 iters 12：

| prefix key | 总 `Lk` | A | B | C | vs 286 |
|---:|---:|---:|---:|---:|---:|
| 286 | 337 | 206.48 | 206.56 | 206.39 | 1.000× |
| 240 | 291 | 203.37 | — | — | 0.985× |
| **223** | **274** | **188.23** | **188.31** | **188.17** | **0.912×** |
| 214 | 265 | **204.14** | **204.31** | **203.99** | 0.989× |
| 192 | 243 | 190.70 | — | — | 0.924× |
| 143 | 194 | 182.06 | — | — | 0.882× |

> **223 个 key 比 214 个 key 快 15.9 ms**（三次分别 15.91 / 16.00 / 15.82，散布 ±0.09）。
> **活儿严格更多，却快 7.8%。** 所以它不可能是工作量。
>
> 快分支 `Lk ∈ {274, 243, 194}`，慢分支 `Lk ∈ {337, 291, 265}`。
> ⇒ **206.22 ms 的基线里至少 16 ms（7.8%）是内核配置，不是工作量。**

同一效应在 2 步和 4 步上按比例复现，比值**一模一样**，所以它是 per-layer-step 的：

| steps | 286 key | 223 key | 比值 |
|---:|---:|---:|---:|
| 10 | 206.48 | 188.23 | **0.912×** |
| 4 | 83.13 | 75.81 | **0.912×** |
| 2 | 41.79 | 38.21 | **0.914×** |

### 5.2 后果：P2 值 −18.2 ms，而且收益主要不来自删列

PHASE9 §3 的发现是 denoise 掩码**按列一致**，所以 63 个无效 prefix 列可以在
`prefix_fill` 之后**压掉一次**，而不是被掩 360 次：286 → **223** 有效槽，`Lk` 337 → **274**。
这是**精确代数**，没有精度闸门。§6 给它定的价是 **−10.9 ms**。

| | |
|---|---:|
| PHASE9 §6 的估值 | −10.9 ms |
| **本节实测（206.48 → 188.23，三次）** | **−18.2 ms** |

但删了多少列**完全不预测收益**：

| 删掉的 prefix 列 | 收益 |
|---:|---:|
| 46（286→240） | −3.1 ms |
| **63（286→223，P2 的真实目标）** | **−18.2 ms** |
| 72（286→214） | −2.3 ms |

> **P2 的收益主要来自它的长度落在快分支上，不是来自删那 63 列。**
> 而 PHASE9 §3 本来就要求这个压缩后的长度**按 bucket 取整**（`dynamic=False` 的要求，
> line 133）——**也就是说 bucket 是个自由参数，而它值 16 ms。**
>
> 这条是给实现者的：**别把 223 向上取整到 224 或 256 就完事**，
> 那可能落到慢分支，把 P2 从 −18.2 ms 变成 −2 ms。**按实测选 bucket。**

### 5.3 机制没定位，这是本节的缺口

只量了 6 个长度，「两分支」是每支两点推出来的，**不是一张图**。候选机制两个，
都没验：(a) inductor 按 shape 自动调优，不同 shape 落到质量差很多的 config；
(b) 融合掩码 attention 内核的分块/对齐悬崖。

区分方法：把每个 shape 下 inductor 选的 config 打出来
（`TORCH_LOGS=+inductor`，或直接读生成的内核源码）。**没做。**
在定位之前，§5.2 那条建议（按实测选 bucket）成立，而「哪些 bucket 快」需要一次密扫。

## 8. 方法论：三个这次学到的

**① 「X 不是瓶颈」必须在出货路径上重量——而 `k` 也是「X」。** §8 ⑤ 说过 eager
的曲线形状不能外推到编译路径。本阶段发现**慢设备的相对速度本身**也是这样的量：
eager `k` = 4.25，编译 `k` = 9.36，2.2× 之差，而 §3.3 的不等式在两条路径上**符号相反**。
> 在 eager 路径上算两设备的账，会得到一个「可以试试」的错误许可。

**② 单调性要验，不能假设。** §1.1 用 286/143/72/8 四点画出一条看着单调的曲线，
§5.1 在同一条曲线上加两点就出现 16 ms 的反转（223 快于 214）。
Phase 14 注意到了非线性但「没有追下去」，而追下去的那 16 ms 比整个 attention 桶
能给任何并行方案的 3.4 ms 大 4.7 倍。
> **稀疏扫描出来的「趋势」不是趋势，是四个点。** 要把一条曲线当结论用，先加密。

**③ 必要条件和充分条件要分开报。** §3 的不等式在 eager 路径上**为真**，而实测
eager SP 是 0.18×——因为 `f* = 1/(1+k)` 假设完美可分，而 SP 复制权重。
把它当充分条件用会得出「eager 下切分该赢」。
> 只报「为假」的那一侧，并且明确写出它是必要条件。

## 9. 没测的，和不能拿这次结果说的话

* **没有穷举异步/过时/投机类的切法。** §3.7 说明本定理**不**约束它们。
  一个并行的设计空间穷举（6 个 lens + 对抗定价）跑到一半会话结束，
  **没有结论可引用**。所以本文件**不说**「没有未被证伪的变体」。
* **仍然没有跑过编译的两进程切分。** Phase 14 §9 的理由不变：
  `transport.send/recv` 是 host 侧调用，`fullgraph=True` 的图里放不下。
  §3 的账是用四个独立实测项算的，**不是跑出来的**；它的结论不依赖那四项如何重叠。
  真要跑，需要在每次交换处主动开图断点，那是另一件工程。
* **§5 的机制没定位**，只有 6 个长度、两分支各两点。密扫 + dump inductor config
  是下一步。在那之前「哪些 bucket 快」不知道，只知道**bucket 值 16 ms**。
* **`c₀ = 337.5 µs` 不是硬件提交地板**，是 eager 下 11 算子 `block_attention` 的成本。
  §3 的结论在 `c₀ = 0` 时依然成立，所以不依赖它；但别拿它论证「iGPU 的队列很慢」。
* **iGPU 的编译数只有 50 行和 24 行两点。** 「0 行 ~1493 ms」是两点斜率外推，
  不是实测。它比算术地板 937.2 高 59%，方向合理，但要引用请标外推。
* **只量了 B=1。** §F2 说 B=4 是带宽交叉点，§M §5 量到 `k` 从 B=1 的 4.75 涨到
  B=4 的 10.40。本阶段所有数都是 B=1。
* **两条 share 曲线都带 `sp_predict_velocity` 的 +13% 重写税**（§4 的对照行：
  512.30 对 453.98）。比值不受影响（分子分母同税），绝对值受。
  §2 的 `k = 9.36` 是比值，所以干净；§1.2 的 196.02 不要和 §1.1 的 206.22 混用。
* **精度只在基础 checkpoint、随机相机帧、固定 prompt 上量过。** rms 1.202e-3 是
  数值结论，不是机器人行为结论。§6 那张真值表来自 PHASE13，样本量 6。
* **没有碰 `vllm_omni/`。** 本阶段不落生产。

```bash

P=spikes/lingbot_vla_v2/phase14_ring_attention_probe.py

# §1.1 + §1.2 — dGPU 的两条曲线。这是 §3 的分子，~6 min，不需要第二张卡
docker exec $D bash -lc "cd $R && ZE_AFFINITY_MASK=0 PYTHONPATH=. python $P \

    --row-shares 51,26,13,1 --loop-prefix 286,143,72,8 --model $M --iters 5"

# §2 — 编译后的 iGPU。本阶段最关键的新数，~8 min

    --row-shares 51,25,1 --key-shares 286,143,8,1 --model $M --iters 3 --warmup 2"

# §1.3 — 纯电线。两端不加载权重、不跑 kernel，~1 min，要两张卡
docker exec $D bash -lc "cd $R && ZE_AFFINITY_MASK=0 PYTHONPATH=. python $P \

    --wire-iters 300 --model $M"

docker exec $D bash -lc "cd $R && ZE_AFFINITY_MASK=0 PYTHONPATH=. python $P \
    --arm ring-2p --split seq --transport shm --worker-cpu 10-11 \
    --model $M --iters 3 --warmup 2"

# §5 — 锯齿。223 vs 214 是本节的全部，iters 12 三次重复，~5 min/次
docker exec $D bash -lc "cd $R && ZE_AFFINITY_MASK=0 PYTHONPATH=. python $P \
    --arm share-sweep --sweep loop --compile-denoise-step \
    --loop-prefix 286,240,223,214,192,143 --model $M --iters 6"

# §6 — 步数。同一条命令换 --num-steps，~4 min/个
for S in 2 4; do
  docker exec $D bash -lc "cd $R && ZE_AFFINITY_MASK=0 PYTHONPATH=. python $P \
      --arm share-sweep --sweep loop --compile-denoise-step --num-steps $S \
      --loop-prefix 286,223,143 --model $M --iters 5"

```

**两张卡的 arm 不要并发**（§L §6），每个 arm 之间等 load 掉到 1.0 以下（Rules #2）。
本阶段每次启动的 load1m 都在日志里，全部 < 1.0。
`--sweep loop` 截断 prefix 之后**输出没有意义**（suffix 看到的 prefix token 变少了）——
那一组**只量成本，不量行为**，这也正是它能给 P2 定价的原因（P2 是精确压缩，`Lk` 相同）。
